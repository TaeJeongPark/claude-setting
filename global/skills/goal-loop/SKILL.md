# 목표 루프

## 0. 루프 정의 (시작 전에 확정)

다음 네 가지를 정하고 사용자에게 한 줄씩 보여준 뒤 바로 시작한다. 인자에 없으면 코드에서 합리적으로 정한다.

- **목표**: 무엇이 참이 되면 끝인가
- **검증 명령**: 목표 달성을 판정하는 명령과 성공 기준(종료 코드, 출력 패턴, 수치). 명령으로 판정할 수 없는 목표면 루프를 시작하지 말고 판정 방법을 먼저 정한다.
- **최대 반복**: 기본 8회
- **범위**: 수정해도 되는 파일·모듈. 목표 달성을 위해 범위 밖을 바꿔야 하면 멈추고 묻는다.

## 1. 기준선

검증 명령을 한 번 실행해 현재 상태를 기록한다(실패 수, 에러 목록, 수치). 이미 목표를 만족하면 그렇게 보고하고 끝낸다.

## 2. 반복

매 반복마다:

1. **진단**: 직전 검증 출력에서 실패 하나(또는 같은 원인으로 묶이는 실패 묶음)를 고른다. 근본 원인을 코드에서 확인한다.
2. **가설과 수정**: 원인에 대한 가설을 한 줄로 적고, 그 가설을 검증하는 최소 수정을 한다.
3. **검증**: 검증 명령을 다시 실행한다. 전체가 오래 걸리면 고친 부분만 먼저 확인하고, 통과하면 전체를 돌린다.
4. **기록**: 할 일 목록(TaskCreate/TaskUpdate)이나 작업 메모에 `반복 N | 가설 | 수정 | 결과(지표 변화)`를 남긴다. 컨텍스트가 압축돼도 이어갈 수 있게 한다.

규칙:

- 이미 실패한 접근을 반복하지 않는다. 같은 실패가 두 번의 다른 접근으로도 안 풀리면 그 항목은 멈추고 다른 항목으로 넘어가거나 보고한다.
- 지표가 나빠지면 그 수정을 되돌린다.
- 테스트를 지우거나 건너뛰거나 기대값을 결과에 맞추는 것은 목표 달성이 아니다.
- 검증 명령 자체를 바꾸지 않는다(사용자 승인 없이).

## 3. 정지 조건

- ✅ 검증 명령이 성공 기준을 만족 → 전체 검증을 한 번 더 돌려 확인하고 끝낸다.
- ⛔ 최대 반복 도달
- ⛔ 2회 연속 지표 개선 없음
- ⛔ 범위 밖 변경이나 사람의 결정이 필요함

## 4. 보고

```
  1. 가설 … → 수정 … → 실패 12 → 7
  2. …
남은 문제와 다음에 시도할 것: …
```
